# 客户验收标准与复盘

阶段 4 的权威参考。验收是训练闭环的收口：学习者要体验"交付被客户审"的完整压力，也要拿到有针对性的复盘。

## 验收准备

1. 要求学习者给出：改动清单（改了哪些文件、各干了什么）+ 自测结果（跑了什么、结果如何）。
2. AI 扮演客户，**先看业务结果，再看代码**——客户验收顺序是"功能对不对 → 边界稳不稳 → 实现清不清晰"。
3. **先尝试运行（硬性步骤）**：
   - **运行前副作用评估**：运行可能产生不可逆外部影响（外发请求 / 写远端数据库 / 删文件 / 触发付费 API）时，先征得学习者确认；学习者不确定或拒绝 → 退回代码走查，并在验收报告中注明"学习者未确认运行"。
   - 项目可运行 → AI **先尝试实际运行关键路径**（跑 `pytest` / 启动服务 / 跑 CLI 命令验证），再走代码走查。启动长驻服务（Web 服务等）时设超时，关键路径验证完即停止进程。
   - 项目不可运行（环境问题 / 学习者明示无法跑 / 测试需要外部依赖如数据库但未配置）→ 走代码走查，并在验收报告里注明"基于代码走查"。
   - 运行产出（log / 临时文件 / `__pycache__`）只用作验收依据，**不主动 `git add`，运行完提示学习者自行清理**。
4. 验收顺序固定：**先运行验证，再代码走查**——避免只看代码不看运行的"纸面验收"。

## 逐条核对

对照需求卡验收标准逐条过，每条给出结论（通过 / 不通过 / 部分通过）：

1. **主流程**：核心功能是否按需求工作？
2. **边界案例**：需求卡中明确的边界（金额为 0、空数据、重复提交、超长输入）是否处理？
3. **健壮性**：异常路径是否友好（不是 500 裸堆栈 / 静默吞错）？
4. **改动范围**：是否只动了必要文件？有没有误伤现有功能（回归）？
5. **需求贴合度**：有没有做偏（客户要 A 做成了 B）？

## 评分维度（1-5 分，五维雷达）

| 维度 | 1 分（很差） | 3 分（及格） | 5 分（优秀） |
|---|---|---|---|
| **需求理解** | 复述跑偏，需客户多次纠正 | 复述准确但带技术词 | 复述准确，主动澄清模糊点 |
| **问题拆解** | 一上来扎进细节 / 拆解顺序乱 | 拆成几步但顺序可优化 | 拆解清晰、顺序合理、含自测考虑 |
| **自主排错** | 每行都问，求助前不自查 | 求助 1-2 次，求助前有自查 | 求助 ≤1 次，求助前精准检索 |
| **工程习惯** | 无测试、命名乱、误伤现有代码 | 有基本测试、命名清晰 | 测试覆盖到位、命名规范、无回归 |
| **沟通** | 求助信号弱（"帮我看看"） | 求助时能描述卡点 | 求助时主动给三段式描述 |

评分说明：
- 首轮无基线时，分数作为后续对比基线
- 多轮后，分数趋势（上升 / 持平 / 下降）比绝对值更有训练价值
- 1 分和 5 分要给具体行为支撑，不写"还行"这种和稀泥的分数

## 验收结论

- **通过**：全部验收标准达成，五维评分均 ≥3。
- **有条件通过（打回重做）**：存在业务级缺陷，或某维度 <3。客户口吻指出缺什么（"客户要求的 X 场景没覆盖到"），**不指出怎么改**，让学习者自己补。
- 打回后学习者再次交付 → 重新走验收流程，最多 2 轮；第 3 轮仍不过，**例外**进入阶段 3 指导模式帮其定位（详见 `references/guidance-ethics.md` 的例外条款），但代码仍由学习者写。

## 复盘报告（必须输出）

用 `assets/templates/retro-report.md` 输出，五个维度 + 评分 + 跨轮对比：

1. **需求理解**：需求复述是否准确？有没有做偏？模糊点是否主动澄清？
2. **问题拆解**：是否把大任务拆成可执行的小步？拆解顺序是否合理？
3. **自主排错**：求助了几次、卡点类型（语法 / 逻辑 / 架构）、求助质量（是否先自查过）。
4. **工程习惯**：自测覆盖、命名、代码组织、有无留下调试残留。
5. **职场视角**：真实团队里这份交付会被打回吗？哪一点最容易在评审会上被挑战？

复盘要点：**具体到本次交付的事实**，不写套话；每条结论给"事实 → 判断 → 建议"结构。

## 跨轮成长闭环

复盘报告必须包含"上轮对比"字段：

- 读取学习者项目根目录的 `SPRINT-RETRO.md`（若存在）
- 列出上轮五维分数 → 本轮分数 → 趋势（↑/→/↓）
- 至少指出一个进步维度 + 一个退步或持平维度（避免"全进步"的伪复盘）
- 鼓励学习者追加保存本轮复盘到 `SPRINT-RETRO.md`

## 收尾

- 询问学习者是否开启下一轮 Sprint：换难度（L1↔L2↔L3）、换需求方向、或换项目。
- **AI 主动换档建议**：基于本轮"自主排错"维度分数主动建议升降档（详见 `references/demand-generation.md` 的换档规则）：
  - 自主排错 ≥4 → 升一档
  - 自主排错 =3 → 保持
  - 自主排错 ≤2 → 降一档，或保持但缩小需求范围
- 鼓励学习者把本轮复盘追加到 `SPRINT-RETRO.md`，形成个人成长记录。
