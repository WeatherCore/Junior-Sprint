# Sprint State 跨轮持久化机制

长 Sprint（L3 半天以上）或学习者明确要求跨多轮对话时，AI 必须维护一个状态文件，防止会话失忆导致"每轮都从零开始"的训练幻觉。

## 触发条件

- 学习者明确说要分多次完成（"我先做到这里，明天接着干"）
- 当前需求是 L3（系统重构，参考时长半天以上）
- 学习者换了对话窗口回来继续之前的 Sprint
- 任何一轮 Sprint 进入阶段 4 后，准备开启下一轮时

## 持久化策略

**学习者持有，AI 只生成模板提示**——AI 不主动写入学习者项目目录（除非学习者明确要求）。这是为了尊重"AI 不污染学习者代码库"的硬约束。

工作流：

1. 触发时，AI 按本目录下 `assets/templates/sprint-state.md` 的模板生成当前状态快照。
2. 提示学习者：把这段内容保存到 `<项目根目录>/.junior-sprint/state.md`。
3. 下一轮对话恢复时，AI 先读 `.junior-sprint/state.md`，确认上一轮进行到哪个阶段、已交付什么、卡点记录。
4. 下一轮 Sprint 启动时（阶段 0 完成后），AI 必读项目根目录的 `SPRINT-RETRO.md`（若存在），做"上轮 → 本轮"的成长对比，避免训练幻觉。

## 状态文件字段说明

详见 `assets/templates/sprint-state.md` 模板内的字段注释。关键字段：

- **current_stage**：当前所在阶段（0/1/2/3/4）
- **difficulty**：难度档（L1/L2/L3）
- **demand_card_snapshot**：本轮需求卡关键内容快照（背景 / 要什么 / 验收标准）
- **delivered_steps**：学习者已完成的实质步骤清单
- **stuck_log**：卡点记录（卡在哪、梯度走到第几级、解决与否）
- **last_retro_ref**：上轮复盘的关键摘要（自主排错维度分数、亮点、改进点）
- **session_count**：本轮 Sprint 已进行到第几次对话

## 防失忆最小集

如果学习者懒得维护完整状态文件，AI 至少要在对话结尾总结以下"防失忆最小集"并提示保存：

1. 当前阶段 + 难度档
2. 已交付什么（一句话）
3. 当前卡点（如有）
4. 上轮复盘一句话总结

这四条信息足以让下一轮对话平滑接续。

## 与复盘报告的关系

- **状态文件（state.md）**：会话进行中用，记录"我现在做到哪了"
- **复盘报告（SPRINT-RETRO.md）**：会话结束后用，记录"这轮我学到了什么"

两者互补：state 是"过程日志"，retro 是"成长档案"。下一轮启动时，AI 两个都读：state 看进度，retro 看成长基线。
